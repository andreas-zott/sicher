1. Überblick & Architektur

Die Anwendung ist eine rein clientseitige, statische Web-App (kein Backend, keine Datenbank, kein Server-Rendering). Jede Seite ist eine eigenständige HTML-Datei; das Portal-Grundgerüst (Login, Übersicht, Anleitung, Fotoformular, Checklisten-Menü, Rechtliches) teilt sich seit der Überarbeitung ein gemeinsames Stylesheet (css/styles.css) und eine gemeinsame Logik-Datei (js/common.js) für Dark Mode, Fußzeile und Service-Worker-Registrierung — zuvor war das auf jeder Seite einzeln kopiert.

Alle Dateien liegen unter dem gemeinsamen Pfad /sicher/ (GitHub Pages) und werden als installierbare Progressive Web App (PWA) ausgeliefert, sodass sie auf iPad/iPhone zum Home-Bildschirm hinzugefügt werden und offline funktionieren kann.

3. Datenfluss zwischen den Seiten

liste-neu.html / mobile-neu.html / audit.html → foto.html

Beim Wechsel zur Foto-Seite werden Marktnummer, Teilnehmer und SiFa als URL-Parameter (?marktnummer=…&name=…&sifa=…) übergeben und dort beim Laden automatisch in die passenden Felder eingetragen.

liste.html / liste-neu.html / mobile.html / mobile-neu.html → massnahmen-sifa.html

Beim Exportieren der Defizite werden die gesammelten Maßnahmen sowie Metadaten (Datum, Markt, Marktleitung, Name, SiFa) VOR dem Öffnen in localStorage geschrieben (Schlüssel massnahmen_uebergabe) — massnahmen-sifa.html liest diesen Stand beim Laden direkt aus. Das ist der zuverlässige Hauptweg, unabhängig von Pop-up-Blockern oder Fenster-Beziehungen. Zusätzlich wird weiterhin window.postMessage() versucht, falls beide Fenster bereits offen sind.

audit.html → Maßnahmenplan.html

Der „Maßnahmenplan"-Button öffnet Maßnahmenplan.html in einem neuen Fenster und übergibt die Daten als URL-Parameter (?data=…, JSON-kodiert).

audit.html → save.php (NAS)

„Direkt auf NAS speichern" sendet die vollständige Begehung per fetch() als JSON an save.php, das die Datei auf der Synology ablegt und Erfolg/Fehler als JSON-Antwort zurückgibt. Erwartet unter companyInfo.datum und companyInfo.marktnummer die Pflichtangaben, sonst wird mit einer klaren Fehlermeldung abgelehnt.

Innerhalb einer Seite

Formulareingaben werden fortlaufend automatisch im localStorage des Browsers zwischengespeichert, sodass ein versehentlich geschlossener Tab die Eingaben nicht verliert.

4. Eingesetzte Bibliotheken

Das Portal-Grundgerüst sowie liste-neu.html, mobile-neu.html und massnahmen-sifa.html binden alle Bibliotheken lokal ein (lib/), ohne Laufzeit-Anfrage an ein CDN. Die älteren Dateien (liste.html, mobile.html, audit.html, theke.html) laden ihre Bibliotheken noch per CDN — Umstellung auf lokale Einbindung steht für diese Seiten noch aus. aushang.html benötigt keine externen Bibliotheken.

5. PWA, Manifest & Service Worker

manifest.json definiert Name, Icons, Start-URL sowie theme_color (#0a2f73, passend zur neuen Portal-Farbe) und eine eigene version-Angabe.

service-worker.js übernimmt das Offline-Caching (Cache-First-Strategie, versionierter Cache-Name, alte Caches werden beim Aktivieren automatisch gelöscht).

6. Datenspeicherung & Datenschutz

  • Für den Großteil der App gilt: keine Serverkommunikation, keine Übertragung an Dritte. Ausnahme: audit.html kann optional per „Direkt auf NAS speichern" die komplette Begehung an den eigenen Server (Synology) senden — bewusste Funktion, kein Dritter beteiligt.
  • localStorage wird für den Formularstand der Checklisten sowie das Theme (hell/dunkel) genutzt.
  • Fotos, Unterschrift und generierte PDFs verbleiben nur im Arbeitsspeicher des Browsers, bis sie manuell heruntergeladen, geteilt oder (nur bei audit.html) aktiv auf die eigene NAS gespeichert werden.
  • Der Service-Worker-Cache enthält ausschließlich die statischen App-Dateien selbst, keine Nutzereingaben.

Ausführliche rechtliche Formulierung: siehe Datenschutzerklärung.

7. Kompatibilität & bekannte Einschränkungen

  • Zielplattform: iPadOS/iOS Safari (Web-Share-API mit Dateianhang, Kamera-Capture, Touch-Bedienung).
  • Die native „Teilen"-Funktion (navigator.share mit Dateien) wird nicht von allen Browsern/Desktop-Systemen unterstützt; in diesem Fall fällt die App automatisch auf einen normalen PDF-Download zurück.
  • Sehr große Foto-Mengen (deutlich über 20–30 Fotos) können die PDF-Erzeugung im Browser spürbar verlangsamen.
  • Der Login (index.html) prüft Benutzername/Passwort rein clientseitig im JavaScript — eine organisatorische Zugriffshürde, kein echter Zugriffsschutz. Bewusst so belassen.
  • audit.htmls NAS-Speichern (save.php) funktioniert nur, wenn die Seite direkt über die Synology (bzw. deren Tailscale-Adresse) aufgerufen wird — über GitHub Pages allein ist der Endpunkt nicht erreichbar, da dort keine serverseitigen Skripte laufen können.
  • Mehrere ältere Dateivarianten (u. a. liste-alt.html, foto2.html, audit-iphone.html, mehrere massnahmen*.html-Varianten sowie diverse unverlinkte Themenseiten) liegen noch im Repository, sind aber nicht Teil der Navigation.
